# Windows 系统故障分析系统 (winhelper)

通过对 Windows 系统日志的全面解析，精准分析可能的故障原因。
**C/S 桌面架构**：双击即用，无 HTTP 服务、无端口占用、完全离线。

---

## 架构设计

```
┌─────────────────────────────────────────────┐
│  桌面壳 desktop.py (pywebview/WebView2)      │
│         │ JS桥接 (无HTTP, pywebview js_api)  │
│         ▼                                   │
│  bridge.py → service.py (handle_* 业务处理器)│
│         ├─→ disk_cleanup.py  磁盘清理引擎    │
│         ├─→ appdata_scan.py  应用数据/安装包  │
│         └─→ log_reader.py    故障分析引擎     │
└─────────────────────────────────────────────┘
```

### 传输层

前端 `web/app.js` 的 `apiFetch()` 检测到 `window.pywebview.api` 后走 JS 桥接直连
Python（`bridge.py::ApiBridge`），无任何 HTTP 参与。

## 打包与分发原理

应用完全基于 **Python 3.12** 开发（桌面壳 `desktop.py`、JS 桥 `bridge.py`、各业务服务引擎），前端界面为 HTML/JS 由 Edge WebView2 渲染。发布产物 `winhelper.exe` 经 **PyInstaller** 打包——**自带一整套私有 Python 运行时**，因此目标机器无需安装 Python、pip 或任何依赖，解压即用：

```
winhelper.exe（约 200MB）内部结构：
├─ Python 解释器本体（python312.dll）      ← 拷贝进来的，不调用系统 Python
├─ 标准库（编译为 .pyc 字节码）
├─ 全部第三方依赖（pywebview、psutil、cryptography…）
├─ 前端资源（web/*.html/js、平台 CA 证书、iperf3.exe 等）
└─ PyInstaller 引导器（bootloader）
```

**运行过程**：双击 → 引导器把内容自解压到临时目录（`%TEMP%\_MEIxxxxx`，代码中引用的 `_MEIPASS` 即此）→ 加载自带的 `python312.dll` 在进程内初始化 Python → 执行打包好的业务代码。目标机器最低要求仅「Windows 10/11 x64」。

常见现象对照：

| 现象 | 解释 |
|---|---|
| 任务管理器里出现两个 winhelper.exe | onefile 模式的引导进程 + 实际运行进程，属正常 |
| 代码中的 `_MEIPASS` 路径 | 运行期解压目录，CA 证书、iperf3.exe 等捆绑资源从此读取 |
| 安装包体积 200MB 出头 | 解释器 + 依赖 + 资源全部内置的代价 |
| 强杀进程后偶尔文件锁定 | 解压目录句柄未释放 |

**唯一外部依赖**是 Edge WebView2 运行时（UI 渲染用）：Win11 系统自带；Win10 缺失时安装包内的 `MicrosoftEdgeWebView2RuntimeInstallerX64.exe` 会自动静默补装（见 `installer\EyeTerm.iss` 的 `CurStepChanged` 逻辑）。

**安全须知**：PyInstaller 是「打包」而非「编译」——字节码理论上可被解包提取，因此本项目铁律为**凭据零硬编码进 exe**（token/密码一律运行时从配置文件或环境变量读取）。

## 目录结构

```
winhelper/
├── desktop.py          # ★ C/S 桌面入口（双击即用）
├── service.py          #    服务层：全部 handle_* 业务处理器
├── bridge.py           #    JS桥接层（桌面数据通道）
├── log_reader.py       #    数据层：事件日志读取 + 故障分析引擎
├── disk_cleanup.py     #    磁盘清理引擎（分类/目录树/推荐/任务管理）
├── appdata_scan.py     #    应用数据盘点/迁移/安装包引擎
├── web/                #    前端（纯静态）
│   ├── index.html
│   ├── style.css
│   ├── app.js          #    传输适配层 apiFetch()
│   ├── disk.js         #    磁盘清理模块前端
│   ├── appdata.js      #    应用数据模块前端
│   └── vendor/
│       └── chart.umd.min.js   # Chart.js 本地化（离线可用）
├── app.ico             #    应用图标
├── winhelper.spec      #    PyInstaller 打包配置
├── build_exe.bat       #    一键构建脚本
└── requirements.txt
```

> 注：磁盘清理功能已拆分为独立项目 `disk-cleaner/`（由专属子 agent 维护演进），
> winhelper 内嵌同源副本，发布时从独立项目同步。
> 旧版 `templates/`、`static/` 为遗留目录，代码已不再引用，可自行删除。

## 使用方式

### 方式一：终端单机使用（推荐）

1. 在任意有 Python 环境的机器上执行 `build_exe.bat` 构建一次
2. 将产出的 `dist\winhelper.exe` 复制到目标终端机
3. **双击即用** — 无需安装 Python、无需配置、无需网络

### 方式二：源码直接运行桌面模式

```powershell
pip install -r requirements.txt
python desktop.py
```

## 磁盘清理 — 安全分级模型

> 设计原则：**数据安全优先**。大量数据文件很敏感，绝不能随意清理。

### 🟢 安全级（支持一键清理 / 勾选个性化清理）

| 分类 | 说明 |
|---|---|
| 回收站 | WinAPI 直接清空（SHQueryRecycleBinW / SHEmptyRecycleBinW） |
| 系统临时文件 | `C:\Windows\Temp` |
| 用户临时文件 | `%TEMP%`（自动保护应用自身运行时 `_MEI*` 文件） |
| Windows 更新下载缓存 | `SoftwareDistribution\Download` |
| 传递优化缓存 | Windows 更新 P2P 分发缓存 |
| 缩略图缓存 | `thumbcache*.db / iconcache*.db`，删除后自动重建 |
| Windows 错误报告 | WER 队列与归档 |
| DirectX 着色器缓存 | 首次启动自动重新编译 |
| 浏览器缓存 | Chrome / Edge / Firefox（运行中被占用的文件自动跳过） |

### 🟡 谨慎级（默认不勾选，显式确认后才清理）

| 分类 | 说明 |
|---|---|
| 内存转储文件 | 蓝屏/崩溃排查证据，建议保留 |
| Windows.old | 系统升级备份，确认稳定后可删 |

### 🔴 敏感级（容量定位分析 — 只定位分析，推荐手动处理）

**🎯 智能推荐 · 建议清理 TOP10 文件夹**（扫描完成后自动优先展示的分析视图）：

- 启发式引擎：12 类目录特征匹配（缓存/临时/日志/崩溃转储/更新缓存/着色器缓存/浏览器缓存/开发工具缓存/升级备份/预读取…）
- 海量小文件目录自动加分（清理效率权重）
- 按预期可释放量排序，**父子目录重叠自动去重**
- **个人数据目录排除**：桌面/文档/下载/图片/视频/微信/QQ 等一律不自动推荐
- 每项给出：容量、文件数、类别、**可清理度（高/中/低）**、推荐理由、处理建议、一键下钻/定位

**目录树容量分析**（WinDirStat 式逐级定位）：

- **扫描范围**：全部本地磁盘（C/D/F/G…动态枚举）或**任意自定义目录**
- **树状下钻**：一次扫描构建完整内存目录树，点击目录名逐层下钻（面包屑导航，无需重扫）
- **每层展示**：容量、文件数、子目录数、文件均值
- **海量小文件识别**：`文件数≥300 且 平均文件≤256KB` 的目录自动标记（应用日志/缓存类），
  支持**按文件数排序**快速发现此类目录——清理效率往往比删大文件更高
- **双排序**：按容量 / 按文件数
- 大文件 TOP25 随树扫描一并生成（阈值可调 50/100/200/500MB）
- 仅定位与建议，提供「打开位置」由用户人工处理，应用内不提供删除入口

### 安全防护机制

1. 清理白名单硬编码于服务端（`disk_cleanup.py`），前端只能传分类 key，无法传任意路径
2. 非法分类 key 同步前置校验，直接拒绝
3. 清理任务互斥锁，防止并发清理
4. 被占用/无权限文件自动跳过并计入统计，不中断整体流程
5. 清理完成后自动重新扫描，数据实时刷新

## 应用数据盘点与迁移助手

> 场景：微信/QQ/钉钉/腾讯会议/桌面/下载产生大量文件堆积，直接清理易造成不可逆数据丢失。

### 分级盘点（区域 → 分类 → 文件 三层展示）

| 区域 | 扫描位置 | 分类方式 |
|---|---|---|
| 微信 | `Documents\WeChat Files`、`xwechat_files`（新旧版本均支持） | 聊天视频/图片/文件/缓存（按 FileStorage、msg 目录聚合） |
| QQ | `Documents\Tencent Files`（含 NT 版） | FileRecv 接收文件 / Image / Video / nt_data |
| 钉钉 | `Documents\DingTalk` | 子目录聚合 |
| 腾讯会议 | `Documents\Tencent Meeting` | 录像等子目录聚合 |
| 桌面 / 下载 | 用户目录 | 按文件类型分组（视频/图片/文档/安装程序/压缩包） |

每个分类展示：大小、文件数、风险等级、路径、**可靠建议**，并给出大文件 TOP25（≥1GB/500MB/100MB 分级徽章）。

### 迁移助手（推荐方式）

- 勾选分类 → 选择目标数据盘（自动列出所有非C盘及剩余空间）→ 一键迁移
- **移动而非删除**，保留相对目录结构；同名同大小自动跳过（防重复），重名自动改名
- 迁移前校验目标盘剩余空间；被占用文件自动跳过并计数
- 微信建议：优先用微信自带「设置→文件管理→更改存储位置」整体迁移；本工具适合迁移「聊天文件」附件类

### 删除辅助（谨慎）

- 仅允许应用数据目录内的路径（服务端白名单前缀校验，同步前置拒绝）
- 删除前强确认对话框（不可恢复提醒）；聊天数据库 db/log 目录扫描时直接排除、绝不触碰
