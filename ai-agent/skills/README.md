# skills/ — 固化 Skill 区

**Skill 是记忆的唯一写入通道。** 绕过 Skill 直接写 `MEMORY.md` = 污染源。

## 为什么要有 Skill

类比"固化技能"：一类任务怎么做、什么算合法产出、边界在哪 —— 全部**写死在声明里**，
由校验器强制。这样：

- **输出可控**：不合 schema 的产出进不了记忆
- **污染可挡**：跨模块写入、乱码、注入、超体积，在入口就被拒
- **行为可审**：为什么拒绝了这次输入，有结构化原因可查

## 目录形态

```
skills/<skill_id>/
  SKILL.md            声明：是什么 / accepts 什么 / 产出什么 / 触发类型 / 边界
  input.schema.json   输入结构约束
  output.schema.json  输出结构约束
  validate.py         校验器（输入拒绝 + 输出把关 + 污染检测）
```

## SKILL.md 模板

```markdown
# Skill: <skill_id>

## 用途
<一句话：这类任务解决什么问题>

## 归属模块
module_id: <module_id>          # 记忆只能写进这个模块，跨模块写入一律拒绝

## 触发类型
交互式 | 事件式 | 定时式        # 决定预算等级：交互式=P0 硬预算

## accepts（接受什么输入）
- <类型描述>：<字段>（必填）
- 明确**不接受**：<列出越界输入>

## 产出（输出什么）
- <结构描述>（须通过 output.schema.json）

## 失败与降级
- 模型链失败 → <降级行为>
- 输入越界   → rejected: out_of_scope + 实际收到的类型
- 校验不过   → 拒绝写入记忆，返回结构化原因

## 边界（不做的事）
- <明确列出>
```

## 校验三道（validate.py 必须实现）

| 道 | 检查 | 不通过 |
|---|---|---|
| **结构** | 对齐 `input.schema.json` / `output.schema.json`（必填、类型、枚举） | `rejected: schema_mismatch` + 缺什么 |
| **语义** | 长度上限、编码合法、**乱码探测**（复用 `server-platform/server/ai.py: _detect_mojibake`）、数值范围 | 拒绝或裁剪，记原因 |
| **来源** | 条目 `module` 是否与本 Skill 归属一致 | 拒绝跨模块写入（防串扰第二道闸） |

## 污染检测五项（写记忆前的守门）

1. **结构越界** —— 出现 schema 未声明字段且非白名单扩展 → 拒
2. **编码异常** —— 命中乱码特征（U+FFFD / UTF-8→GBK 双字 / 成片异常字符集）→ 拒
3. **来源不明** —— 缺 `source` / `ts` → 拒
4. **自相矛盾** —— 与既有条目直接冲突且判不出新旧 → **不自动覆盖**，追加"冲突待裁决"
5. **体积异常** —— 单条 > 4KB → 拒（多半是误把原始日志当记忆）

## 无关内容判定（一律"丢弃 + 回执"，禁止静默）

| 情形 | 回执 |
|---|---|
| 超出 `accepts` 声明范围 | `rejected: out_of_scope` + 实际收到的类型 |
| 空 / 仅空白 / 仅分隔符 | `rejected: empty` |
| 疑似提示注入（夹带"忽略以上指令"类模式） | `rejected: injection_suspected`（**留证**） |
| 结构不符 | `rejected: schema_mismatch` + 缺失字段清单 |

> **铁律**：所有丢弃都必须让调用方拿到**结构化原因**。静默吞掉是禁止项——
> 那会让上游以为"处理成功了"，问题被埋进记忆里。
