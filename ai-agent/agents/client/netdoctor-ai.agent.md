## 2. 服务对象与表达（准则四）✅ **已落地**（2026-09-20 重写 prompt）

| 项 | 值 |
|---|---|
| 主要对象 | **enduser（使用人本人）** |
| 语言要求 | 白话 + 影响 + 下一步动作；**不甩术语** |
| 输出粒度 | "哪里不通 / 影响什么 / 我建议你怎么做" |

**同一结论的两种说法（本配置应采用下面那条）**：

- ❌ 现状（运维版）：`【故障原因分析】DNS 解析失败（network，10:12:03）；建议核查 DNS 服务器配置`
- ✅ 应采用（使用人版）：`你的电脑连不上网站，是因为域名解析出错。我帮你换成公共 DNS（114.114.114.114），
  点一下就能修好`

> **待办 P0-3**：按准则四重写 `_ND_AI_PROMPT_SYSTEM`，保留"证据可信性硬约束"（那部分是好的），
> 但把**输出格式与语言**改为使用人视角。

## 3. 职责与边界

**做**：

- 基于本机采集的网络数据（连通性/延迟/丢包/路由/DNS）给出诊断
- 纯离线场景可用（个人版不依赖中心）

**不做**：

- **不得凭体感下结论**（prompt 已固化"性能类缺证据时的输出约定"）
- 不主动执行修复（只给建议；执行类动作由用户在对应模块点确认）

## 4. 输入契约

| 项 | 要求 |
|---|---|
| 必填 | 问题概述/诊断触发；探测数据至少一类可用 |
| 选填 | 六类网络数据（连通性/延迟/丢包/路由/DNS/带宽）—— 缺失须显式声明 |
| 限幅 | 沿用既有截断设施 |
| 拒绝规则 | 无任何证据 → 输出"缺失证据清单"，**不得凭体感编造**（已固化） |
| **模式分流** | `enterprise` → 走中心 `llm_chat_chain` 转发；`personal` → 本机 urllib 直连第三方 `/v1/chat/completions` |

## 5. 输出契约

| 项 | 要求 |
|---|---|
| 结构 | 三段（现状为【故障原因分析】+【处理意见】+【风险提示】）→ **使用人版应改为口语化三段** |
| 必含 | 缺失证据清单（数据不足时） |
| 禁含 | 编造的事件 ID / 时间戳；个人文件内容 |
| 校验点 | 结果落本机 AI 历史（`/api/netdoctor/ai-history-append`） |

## 6. 预算与降级（准则二 / ADR-006）❌

| 项 | 值 |
|---|---|
| 单次超时（企业版） | 走中心链（现 **25s / max_retries=0**）→ 最坏 **50s** |
| 单次超时（**个人版**） | **30s**（本机直连） |
| 最坏耗时 | 企业版 50s / 个人版 30s ✅ |
| 场景预算 | 30~60s（使用人交互） |
| 失败降级 | 未配置 → 引导设置页；调用失败 → 失败态渲染 |

✅ **2026-09-19 已收紧（ADR-009）**：个人版 120s → 30s（覆盖实测诊断区间）。
⏳ **仍待补**：使用人场景的**进度反馈**（"生成中…" + 可取消）—— 超时收紧了，
但 30s 的静默等待仍不理想；此项需改前端，**未包含在本次超时修复内**。

## 7. 隐私边界（准则五）

| 项 | 值 |
|---|---|
| 数据来源 | **本机采集**（网络探测数据 + 系统网络配置） |
| 是否离机 | ⚠️ **取决于模式**：`enterprise` → **数据经中心转发**（离机）；`personal` → **直连第三方 LLM**（离机，且目的地是外部服务） |
| 禁含 | 个人文件内容、凭据、浏览历史；**非网络诊断必需的任何本机数据** |
| **凭据处理** | `ai_personal.api_key` 存 `%LOCALAPPDATA%\winhelper\app_config.json`（**不入 exe** ✅） |
| 声明方式 | ⚠️ 已有声明（`隐私边界：日志包仅含运维诊断数据…`，位于 `_ND_AI_PROMPT_SYSTEM` 末行），但硬编码在客户端 prompt 字面量里 → 待抽为公共常量<br>**2026-09-20 更正**：原文记"当前无声明"**有误** |

> ⚠️ **本引擎是隐私风险最高的**：个人版会把本机网络数据**发往第三方 LLM**。
> 使用人必须**明确知道**发了什么、发给谁 —— 建议在个人版设置页显式提示
> （符合准则五"他有权知道你看了什么、报了什么"）。
