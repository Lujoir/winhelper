## 2. 服务对象与表达（准则四）

| 项 | 值 |
|---|---|

**表达示例**（本配置采用运维版）：

## 3. 职责与边界

**做**：

- 按可能性排序定位根因，引用日志依据并**注明日志类别**
- 六类日志任一缺失时**显式声明该类证据不足**（不得用其他类推断补位）

**不做**：

- 不臆造日志中不存在的事件 ID（analysis_id=16 事故的教训）
- 不跨越"未注入"与"未采集"的语义（预算未注入的类必须在 prompt 中如实声明）

## 4. 输入契约

| 项 | 要求 |
|---|---|
| 必填 | `issue`（≤2000 字，空或超长 → 400） |
| 选填 | `logs` 六类键（`hwinfo` `os_info` `perf_analysis` `perf_stress` `system_log` `network`）均可缺省 |
| 限幅 | 单类原始/存证 **32KB**（`DIAG_RAW_LIMIT`/`DIAG_EVIDENCE_PER_KEY`）；单类注入 **16KB**（`DIAG_PROMPT_PER_KEY`）；全 prompt 日志总量 **32KB**（`DIAG_PROMPT_TOTAL`） |
| 预算分配 | 优先级贪心：`system_log` 恒第一 → 问题概述关键词命中类提前 → 快照类（`os_info`/`hwinfo`）垫底 |
| 拒绝规则 | `logs` 非对象 → 400；body > 8MB → 413；终端未注册 → 404 |

## 5. 输出契约

| 项 | 要求 |
|---|---|
| 结构 | 【故障原因分析】+【处理意见】+【风险提示】三段 |
| 必含 | 依据注明日志类别；处理意见分两档 |
| 禁含 | 编造事件 ID；无时间戳的引用；用户个人文件内容 |
| 校验点 | `evidence`（每类 ≤32KB 结构感知裁剪）+ `stats` 落库，供事后核对 |
